      Questions

      Good to know

      Is my Supabase anon key safe in the frontend?

      Yes, the anon key is meant to be public. What protects your data is Row Level Security, so every table needs RLS turned on with policies that only let users reach their own rows. The service_role key is different: it must never be in the browser. Supabase security guide.

      How do I check if my API key is exposed on my website?

      Paste your site into the scan above, or open DevTools on your live site and search all JavaScript for prefixes like sk-, sk_live_, AKIA and service_role. How to check for exposed API keys.

      Is my Lovable app secure?

      Lovable apps often work perfectly while leaking secrets: API keys in VITE_ variables, or Supabase tables without Row Level Security. A free scan shows you in about a minute. Lovable security check.

      What does LeakPatrol check?

      Secret API keys in your JavaScript (OpenAI, Anthropic, Stripe, AWS, GitHub, Supabase service keys and more), automation webhook links, public .env files, .git folders and source maps, security headers and HTTPS, and, once you prove you own the site, which Supabase tables can be read without logging in.

      Is it safe to scan my app?

      Yes. We only download what any visitor's browser already downloads, plus a short list of files that should never be public. We never log in, submit forms, or change or delete anything.

      Do you store my keys or data?

      No. If we find a key we show only the first and last few characters, and we never store the full value. Scan results are kept for 10 minutes so repeat scans are quick.

      Can I scan someone else's app?

      Only scan apps you own or have permission to test. The database check only runs after you prove you own the site.

      My app was built with Lovable. Will the fixes work there?

      Yes. Each fix in the full report comes with a prompt written for AI coding tools, so you can paste it into Lovable, Bolt, v0, Replit, Cursor or Claude Code.

      I got an A. Am I completely safe?

      An A means none of the common, visible mistakes we look for. It is not a full security audit, so keep following good practice, especially around who can read and change your data.
